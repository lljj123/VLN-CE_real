# 给别人的项目讲解

## 一句话概括

这是一个让 ROS1 小车根据英文指令和 RGB-D 相机连续做导航动作的 CMA 策略：它每次只输出前进、左转、右转或停止，但用两层 GRU 把前几步看到的画面和做过的动作压缩成记忆。

## 怎么工作的（3 分钟版）

1. 相机提供对齐的彩色图和深度图，预处理模块把它们变成模型固定需要的 224×224 RGB 与 256×256 归一化 Depth。
2. 指令经词嵌入和双向 LSTM 编码；RGB 与 Depth 各自经 ResNet 编成 4×4 空间特征。
3. 第一层 GRU 汇总当前视觉、上一动作和旧记忆，并决定现在该关注指令中的哪些词。
4. 当前指令片段再去选择 RGB/Depth 中最相关的空间位置。
5. 第二层 GRU 把这些信息融合成新的导航记忆，线性动作头输出四类动作。
6. ROS 节点保存两层 GRU 状态和预测动作，下一个决策步继续使用；底盘节点把离散动作变成里程计闭环的 `cmd_vel`。

## 用大白话理解“记忆”

它不是边走边画地图，而是随身带着两张 512 个数字的“便签”。第一张便签帮助它判断指令执行到哪一段、眼下该找什么；第二张便签整合当前看到的东西和指令，决定下一步。每做完一个动作，还会把“刚才做了什么”作为额外线索带到下一步。

第一步时两张便签清空，上一动作使用专门的 START embedding。之后每一步都会覆盖成新便签。若忘记在新任务开始时 reset，上一条路线的历史就会串进下一条路线。

## 训练时需要特别注意的地方

真实轨迹会被切成最多 16 步的小段。每小段内部，误差可以沿 GRU 反传，网络确实在学习时序；但小段之间状态清零，所以微调只能直接训练至多 16 步的上下文。训练还总是告诉模型“专家上一动作”，实机却使用“模型自己上一动作”，错误发生后可能逐步放大。

## 值得注意的设计决策

- 保留 4×4 空间网格：让语言可以选择画面位置，而不是只看整图摘要。
- 两级 GRU：先用历史控制注意力，再把跨模态结果写入最终导航状态。
- 推理训练同模型、同预处理：减少从 Habitat 到 ROS 部署的依赖和输入差异。
- checkpoint 严格加载：保证简化后的纯 PyTorch 实现与原网络参数布局一致。
- 视觉与语言默认冻结：适合小规模真实数据，但把微调重点放在注意力、GRU 与动作头。
